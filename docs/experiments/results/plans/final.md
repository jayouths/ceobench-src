# 最终论文结果分析与呈现方案

## 1. 范围

最终论文只有四个实验组：

```text
baseline
analysis
analysis-deliberation
full
```

本文件不重复设计实验执行流程，只规划最终论文准备回答哪些研究问题、观察哪些指标，以及如何直观呈现指标反映的信息。所有候选指标的定义和数据来源统一维护在 [实验指标目录](../metric-catalog.md)。

## 2. 研究问题与证据设计

### RQ1：完整 Harness 是否改善长期经营结果

这是论文最核心的问题。

| 层级 | 候选指标 | 作用 |
|---|---|---|
| P0 | 最终现金 | CEO-Bench 北极星指标 |
| P0 | 破产率、生存天数 | 防止只在存活样本中比较终态 |
| P0 | 现金轨迹 | 观察优势何时形成、能否持续 |
| P1 | 最大绝对现金回撤、最大现金回撤率 | 从金额和相对降幅两个角度观察资金链风险 |

建议呈现：

- 核心结果表报告四组的最终现金、破产率和生存天数。
- 现金折线图展示四组长期轨迹、波动和破产时点。
- 如终态分布差异重要，可增加每次运行散点或箱线图；否则结果表已经足够。

可以支持的结论：完整 Harness 是否优于 Baseline，以及优势是长期积累还是偶然终态差异。

### RQ2：三个创新模块是否分别产生增量贡献

采用四组递进消融：

```text
Analysis 贡献      = analysis - baseline
Deliberation 贡献  = analysis-deliberation - analysis
Reflection 贡献    = full - analysis-deliberation
总体贡献           = full - baseline
```

候选指标优先使用最终现金，同时观察 MRR、客户规模和 API 成本，避免某个模块只提高现金但损害持续经营能力。

建议呈现：

- 一张消融结果表同时列出四组原始结果和三段边际差额。
- 若边际贡献是论文重点，可用差额点图展示每个模块对最终现金、MRR 和成本的增量；不必为每个模块单独画一张图。

可以支持的结论：每个模块是否有独立增量价值。不能只用 `full vs baseline` 的总体提升反推三个模块都有效。

### RQ3：现金优势是否建立在健康、持续的经营结果上

| 层级 | 候选指标 | 观察角度 |
|---|---|---|
| P0 | 最终 MRR | 持续收入能力 |
| P0 | 活跃个人订阅数 | 个人市场规模 |
| P0 | 企业订阅席位数 | 企业市场规模 |
| P0 | 末四周平均每周净现金流 | 实验末期盈利能力 |
| P1 | 个人与企业流失率 | 增长质量 |
| P1 | 活跃客户群数、MRR 集中度 | 客群多样性与集中风险 |
| P1 | 未解决工单及积压天数 | 是否以牺牲客户服务换取增长 |
| P1 | 累计宕机时间、错误率和延迟 | 是否以牺牲可靠性换取成本优势 |

建议呈现：

- 主图采用保留原始单位的分面点图，每个指标展示每次运行、均值和误差。
- 客户、MRR、服务质量的时序图不是固定主图。只有出现明显增长阶段、转折点或故障期时才补充折线图。
- 高度相关指标只保留更容易解释的一项进入正文，完整结果进入附录表。

可以支持的结论：经营优势是否具有持续性，以及是否存在增长、风险和服务质量之间的代价。

### RQ4：最终现金差额是如何形成的

候选指标为各账本类别的累计金额及实验组相对 Baseline 的差额，包括订阅收入、广告收入、算力、容量、广告与获客、运营、研发和市场研究。

建议呈现：

- 使用瀑布图分解 `full - baseline` 的最终现金差额。
- 消融组的同口径分解优先放结果表或附录，避免正文出现多张结构相同的瀑布图。
- 若“什么时候投入”比“累计投入多少”更重要，再针对关键支出补充分面折线图。

可以支持的结论：Harness 是通过增收、节支还是增加前期投入换取长期回报获得现金优势。

### RQ5：创新模块是否改善经营认知与战略判断

该问题需要按模块拆开观察。

| 模块 | 候选证据 | 建议呈现 |
|---|---|---|
| Analysis | 现金预测绝对百分比误差、偏差方向、区间覆盖率 | 按预测期限的点图或结果表；补充一条可追溯的经营画像案例 |
| Deliberation | 未来经营指标方向命中率、冲突整合案例 | 与简单趋势预测参照比较；用结果表或指标分面点图 |
| Reflection | `full` 相对 `analysis-deliberation` 的方向命中率、重复错误情况 | 两组同口径点图；必要时展示随经营周次变化的命中率 |

Analysis 的 JSON 合法率和证据编号存在率主要证明工程约束生效，不应包装成经营认知能力提升。机制结论应优先依赖预测结果和可追溯案例。

可以支持的结论：经营结果提升是否与更准确的状态理解、未来判断和历史经验利用相一致。

### RQ6：经营提升是否值得额外模型成本

| 层级 | 候选指标 | 作用 |
|---|---|---|
| P0 | 各模块 API 成本 | 识别成本来自哪个模块 |
| P0 | Agent 总 API 成本 | 比较四组整体成本 |
| P0 | 增量 API 成本 | 观察每一步消融增加的代价 |
| P0 | 增量模拟现金 | 观察每一步产生的经营增量 |
| P1 | 单位成本模拟现金增量 | 辅助描述成本收益关系 |
| P1 | 模型调用次数和 Token 构成 | 解释成本来源，不跨模型直接比较效率 |

建议呈现：

- 核心结果表并列报告最终现金与 Agent API 成本。
- 使用“API 成本—最终现金”散点图，每个点表示一次运行，观察各组成本和结果的位置。
- 单位成本增量作为辅助统计，不使用“Token/每周净现金流”这种分母容易失效的指标。

可以支持的结论：额外 Harness 调用带来的经营改善与计算成本之间是否存在合理权衡。模拟现金不能表述为真实商业利润。

### RQ7：结论是否依赖特定环境难度

若默认 CEO-Bench 环境导致所有实验组快速破产，或需要进一步检验方法稳定性，可以预先设置统一的低、中、高难度场景。场景可调整竞争压力、初始资金或其他明确的模拟器难度参数，但同一场景内四个实验组必须使用完全相同的规则。

候选指标沿用 RQ1 至 RQ3 的最终现金、生存天数、MRR 和客户规模，重点观察各模块增益方向是否随难度改变。

建议呈现：

- 使用结果表比较每个难度下四组核心指标。
- 需要展示趋势时，以难度为横轴、相对 Baseline 的现金增量为纵轴绘制点图。
- 不为每个难度重复绘制一整套正文图表。

可以支持的结论：创新模块是否只在某一难度下有效，以及环境过难或过易时是否出现效果边界。默认场景仍承担主结论，降低难度不能作为查看结果后的替代性主实验。

## 4. 条件性补充图

以下图表先采集指标，不预设一定进入正文：

- 客户与 MRR 增长轨迹。
- 每日实际收入及 7 日移动平均。
- 经营支出时序。
- 服务可靠性和过载时序。
- Reflection 命中率随时间变化。

它们只有在提供终态和汇总结果无法表达的阶段、转折或机制信息时才单独成图，否则进入附录或结果表。

## 5. 设计原则

- 先确定研究问题和指标，再选择图表形式。
- P0 指标无论结果是否有利都必须报告。
- 同一指标只有在终态、时序或构成视角回答不同问题时才重复展示。
- 图表保留真实单位，不构造缺乏理论依据的综合得分。
- 图形用于显露数据规律，不能通过双纵轴、随意归一化或平滑制造差异。
