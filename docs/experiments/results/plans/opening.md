# 开题答辩结果分析与呈现方案

## 1. 范围

开题阶段只做第一个创新模块，因此只比较：

```text
baseline
analysis
```

本阶段不回答 Deliberation、Reflection 和完整 Harness 是否有效。开题方案从 [最终论文结果方案](final.md) 中选择 Analysis 已经能够支持的研究问题、指标和图表。

## 2. 开题研究问题

### OQ1：Analysis 是否初步改善长期经营结果

候选指标：

- 最终现金。
- 破产率和生存天数。
- 现金轨迹。
- 最大现金回撤。

建议呈现：

- 一张两组核心结果表。
- 一张 Baseline 与 Analysis 的现金轨迹图。

优先结论：Analysis 是否表现出更高或更稳定的现金结果，以及优势从什么时候开始形成。

### OQ2：Analysis 是否改善持续经营能力，而非只提高现金

候选指标：

- 最终 MRR。
- 活跃个人订阅数。
- 企业订阅席位数。
- 末四周平均每周净现金流。
- 时间允许时补充流失率、宕机时间或工单积压。

建议呈现：

- 使用四个核心指标的分面点图。
- 若重复实验较少，可在结果表中直接展示每次运行，不强行画误差分布。
- 客户和 MRR 折线只在出现明显增长阶段或转折点时补充。

优先结论：现金优势是否伴随持续收入和客户规模改善，是否存在明显经营代价。

### OQ3：Analysis 为什么可能产生改善

候选证据：

- 现金预测绝对百分比误差及偏差方向。
- 各账本类别对最终现金差额的贡献。
- 一周真实的 `signals.json -> role_reports.json -> state_portrait.json -> STRATEGY_BRIEF.md` 案例。
- 战略简报如何影响后续决策 Agent 工具调用的可追溯案例。

建议呈现：

- 优先使用现金差额瀑布图解释增收与节支来源。
- 时间允许时增加现金预测误差点图。
- 方法章节或答辩页展示一条完整信息链，不为 Schema 合法率单独画图。

优先结论：经营结果变化是否与更完整的状态理解、更准确的现金判断或更合理的投入策略一致。

### OQ4：Analysis 的额外成本是否合理

候选指标：

- 决策 Agent API 成本。
- Analysis API 成本。
- Agent 总 API 成本。
- 相对 Baseline 的增量 API 成本。
- 相对 Baseline 的增量模拟现金。

建议呈现：

- 在核心结果表中直接并列最终现金和 API 成本。
- 数据足够时增加“API 成本—最终现金”散点图。
- 不采用不同模型 Token 直接相加，也不采用 Token/每周净现金流比值。

优先结论：Analysis 增加了多少计算成本，这一成本对应了怎样的模拟经营结果变化。

## 3. 开题优先级

### 3.1 必须准备

| 输出 | 指标 | 回答的问题 |
|---|---|---|
| 核心结果表 | 最终现金、生存、MRR、客户规模、末四周净现金流、API 成本 | Analysis 是否有效且代价可控 |
| 现金轨迹图 | 周度现金 | 优势形成过程和稳定性 |
| 多维经营结果图 | MRR、个人订阅、企业席位、末四周净现金流 | 是否具有持续经营价值 |
| Analysis 信息链示例 | 信号、角色报告、经营画像、战略简报、后续决策 | 创新模块具体做了什么 |

### 3.2 时间允许时准备

| 输出 | 使用条件 |
|---|---|
| 现金差额瀑布图 | 需要解释最终现金差异来自哪些收支类别 |
| 现金预测准确性图 | 两组存在足够的成熟预测样本 |
| 成本收益散点图 | 重复运行数量足以观察成本和结果分布 |
| 客户、支出或可靠性时序图 | 出现汇总指标无法表达的阶段性机制 |

## 4. 暂不呈现

- 三个模块的完整递进消融。
- Deliberation 的多角色冲突整合效果。
- Reflection 的历史经验利用效果。
- 经营指标方向预测命中率。
- `full vs baseline` 的总体结论。

这些内容属于最终论文方案，不能用 `baseline vs analysis` 的结果代替。

## 5. 开题结论口径

开题阶段可以形成三层结论：

1. Analysis 能够生成可追溯的经营状态分析并接入原 Bash Agent。
2. Analysis 在当前 CEO-Bench 实验中是否表现出经营结果改善。
3. 这种变化是否伴随持续经营指标、机制证据和合理的额外成本。

证据不足时使用“初步结果表明”或“在当前运行中观察到”，不提前宣称三个创新模块或完整 Harness 已经成立。
