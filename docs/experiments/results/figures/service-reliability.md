# 服务可靠性

## 1. 研究问题

创新模块是否帮助 Agent 更合理地配置容量和运营投入，从而减少过载、宕机和严重服务故障；经营增长是否以牺牲服务质量为代价。

## 2. 候选指标

- 累计宕机时间。
- 严重故障周数。
- 平均或峰值错误率。
- P95 延迟。
- 容量利用率和过载周期数。

指标来自 `world.nmdb/service_day`。错误率和 P95 延迟通常高度相关，不能为了增加图表数量重复展示。

## 3. 建议表达

全周期汇总优先进入多维经营结果或结果表。只有出现稳定的阶段性故障、提前扩容或恢复差异时，才使用周度折线图展开机制；避免将两个高度相关指标放在双纵轴上制造视觉差异。
